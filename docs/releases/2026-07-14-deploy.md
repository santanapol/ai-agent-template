## หมายเหตุ — auto-deploy GitHub Action

`.github/workflows/deploy.yml` ("Deploy to DigitalOcean") ถูก disable ไว้และ fail ต่อเนื่องตั้งแต่ 2026-07-13 ด้วย error "missing `.env.staging`" — ตรวจสอบด้วย SSH ตรงเข้า `143.198.213.26` แล้วพบว่าไฟล์ `.env.staging` ทั้ง 6 ตัวมีอยู่จริงบนเครื่อง ดังนั้นสาเหตุน่าจะอยู่ที่ secret `DO_HOST`/`DO_SSH_KEY` ชี้ผิดเป้าหมายหรือ key ไม่ตรง ไม่ใช่ปัญหาของ staging server เอง — **ไม่บล็อกการ deploy ด้วยมือรอบนี้** แต่ควรแก้ secret แยกต่างหากเพื่อให้ auto-deploy กลับมาใช้งานได้

## หมายเหตุ — `deploy-staging.sh` health-check false negative

รอบ deploy จริง (2026-07-15) script จบด้วย exit 23 ที่ขั้นตอน `curl -sf http://127.0.0.1:3005/ | head -c 200` — สาเหตุคือ `head -c 200` ปิด pipe ก่อน `curl` เขียนข้อมูลเสร็จ ทำให้ curl ได้ broken-pipe (exit 23) ทั้งที่ backoffice ตอบ `200 OK` จริง ยืนยันด้วยการ curl ตรงแบบไม่ pipe (`HTTP_STATUS=200`) และ pm2 ทุก app `online` ปกติ — **ไม่ใช่ deploy fail จริง** แต่ script ควรแก้ pattern นี้ (เช่นใช้ `curl -o /dev/null -w '%{http_code}'` แทนการ pipe เข้า `head`) ในรอบถัดไปเพื่อไม่ให้ false-alarm ซ้ำ
