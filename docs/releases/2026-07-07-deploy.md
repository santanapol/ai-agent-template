## ก่อน merge / deploy (staging server)

- [ ] `bash scripts/staging-verify-env.sh` — `GATEWAY_SHARED_SECRET`, `MONGODB_URI_READ`, `branch-report PORT=3104`
- [ ] ยืนยัน `backend/*/.env.staging` ใช้ชื่อ env ใหม่ (ดู [backend/ENV.md](../../backend/ENV.md))
- [ ] อย่า commit `server-environment/staging/credential.md` หรือ `.env.staging`
- [ ] บันทึก `PREVIOUS_GOOD_SHA=$(git rev-parse HEAD)` ก่อน `git pull`

## หลัง merge — deploy บน staging

```bash
cd /var/www/zero-platform
PREVIOUS_GOOD_SHA=$(git rev-parse HEAD)   # บันทึกก่อน pull
git pull
bash scripts/staging-verify-env.sh
bash scripts/deploy-staging.sh            # install + build:staging + pm2 reload + healthz
pm2 status
```

`deploy-staging.sh` reload: `pm2 reload backend/ecosystem.staging.config.js`

## หลัง deploy — smoke

**จากเครื่อง dev** (ผ่าน Cloudflare + Nginx):

```bash
SMOKE_PASSWORD='…' bash scripts/smoke-staging.sh
# หรือ STAGING_URL=https://zero-staging.168bits.com SMOKE_PASSWORD='…' bash scripts/smoke-staging.sh
```

ตรวจ: frontend shell → `POST /auth/login` → `GET /auth/me/branches` → `GET /api/v1/smart-reports`

## Breaking / migration

| เปลี่ยน | การแก้ |
|--------|--------|
| Harness env | `backend/<service>/.env.harness` แทน `0/env/*` |
| `GATEWAY_SECRET` → `GATEWAY_SHARED_SECRET` | อัปเดต `.env.staging` บน server |
| branch-report `PORT` | ต้องเป็น `3104` (`staging-init-env.sh` patch อัตโนมัติ) |
| Menu permissions | sidebar เก่า → `bash scripts/staging-seed-all.sh` |

## Rollback

**Trigger:** healthz ล้ม, login ล้ม, branch switcher ว่าง, PM2 errored

```bash
cd /var/www/zero-platform
git fetch origin
git reset --hard "$PREVIOUS_GOOD_SHA"
bash scripts/deploy-staging.sh
```

**RTO:** ~5–10 นาที. Schema พังบน staging Docker: `bash scripts/staging-seed-all.sh` (ลบข้อมูล staging เท่านั้น)

## Acknowledged risks (staging)

- Staging อ่าน prod Atlas read replica สำหรับชื่อสาขาจริง
- smart-report VM sandbox — admin-only; AST + runtime pipeline guard
- `credential.md` gitignored only — อย่า commit

## ไม่กระทบ production

- Deploy รอบนี้เป้าหมาย staging เท่านั้น
- `.env.prod` ไม่เปลี่ยนใน PR นี้
